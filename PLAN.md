# План: устройство управления моделью поезда (train-mcu)

## Общее описание

Бортовой контроллер модели поезда на базе ESP32. Подключается по WiFi к пульту
управления (`train-control`), получает команды через MQTT и управляет двигателем,
освещением и звуковым сигналом.

---

## 1. Взаимодействие с пультом управления

### 1.1 Сеть

| Параметр        | Значение                          |
|-----------------|-----------------------------------|
| WiFi SSID       | `TrainControl`                    |
| WiFi пароль     | `train1234`                       |
| WiFi канал      | 6                                 |
| Безопасность    | WPA2-PSK                          |
| IP MQTT-брокера | `192.168.4.1` (IP точки доступа)  |
| Порт MQTT       | `1883`                            |
| QoS             | 0                                 |

Устройство работает как **WiFi STA** (станция) — подключается к AP пульта.

### 1.2 MQTT-топики

| Топик                   | Направление        | Описание                          |
|-------------------------|--------------------|------------------------------------|
| `train/<id>/cmd`        | Пульт → Поезд     | Команды управления                 |
| `train/<id>/state`      | Поезд → Пульт     | Текущее состояние (retained)       |
| `train/<id>/ping`       | Пульт → Поезд     | Запрос статуса                     |
| `train/<id>/pong`       | Поезд → Пульт     | Ответ на ping                      |
| `train/announce`        | Поезд → Пульт     | Объявление при подключении (retained, LWT) |

`<id>` — уникальный идентификатор поезда. По умолчанию генерируется на основе MAC-адреса (например, `L-ABCDEF`) при первой прошивке и сохраняется в NVS. Можно изменить через NVS.

### 1.3 Формат команд (JSON)

#### Управление скоростью
```json
{"action":"speed","value":75}
```
`value`: 0–100, процент от максимальной скорости. 0 = остановка.

#### Плавная остановка
```json
{"action":"stop"}
```
Плавное торможение с учётом настроек инерции.

#### Экстренная остановка
```json
{"action":"estop"}
```
Немедленное отключение двигателя, сброс скорости в 0.

#### Направление
```json
{"action":"direction","value":"forward"}
```
`value`: `"forward"` или `"reverse"`. Применяется **только при скорости 0**.

#### Освещение
```json
{"action":"light","target":"all","value":true}
```
`target`: `"head"`, `"tail"`, `"cabin"`, `"all"`. `value`: `true`/`false`.

#### Звуковой сигнал
```json
{"action":"horn","value":"short"}
```
`value`: `"short"`, `"long"`, `"off"`.

#### Конфигурация
```json
{"action":"config","param":"accel_rate","value":50}
```
`param`: `"accel_rate"`, `"decel_rate"`, `"max_speed"`.

### 1.4 Формат состояния (Поезд → Пульт)

Публикуется в `train/<id>/state` с флагом retained:

```json
{
  "speed": 75,
  "direction": "forward",
  "lights": {"head": true, "tail": false, "cabin": false},
  "battery": 82,
  "error": null,
  "uptime": 3600
}
```

### 1.5 Объявление (announce)

При подключении к брокеру публикуется в `train/announce` (retained):

```json
{"id": "L-ABCDEF", "model": "steam", "fw": "1.0.0"}
```

LWT (Last Will and Testament) — при потере связи брокер удаляет retained-сообщение
из `train/announce`.

## 3. Описание компонентов

### 3.1 `wifi_sta` — подключение к WiFi

- Подключение к AP `TrainControl` с паролем `train1234`
- Автопереподключение при потере связи
- Генерация события при подключении/отключении

### 3.2 `mqtt_client` — MQTT-клиент

- Подключение к брокеру `192.168.4.1:1883`
- Подписка на `train/<id>/cmd` и `train/<id>/ping`
- Публикация announce при подключении
- Настройка LWT: пустое сообщение в `train/announce` при потере связи
- Передача входящих сообщений в `cmd_handler`
- Автопереподключение

### 3.3 `motor_driver` — управление двигателем

- **Аппаратная часть**: H-мост L298 (L298N)
- PWM через LEDC peripheral ESP32
- Плавное ускорение/торможение (рампа скорости)
- Параметры рампы настраиваются (`accel_rate`, `decel_rate`)
- Поддержка `max_speed` — ограничение максимальной скважности PWM
- Экстренная остановка — немедленный сброс PWM в 0

**GPIO (пример)**:

| Сигнал | GPIO | Описание            |
|--------|------|----------------------|
| IN1    | 25   | Направление (канал A)|
| IN2    | 26   | Направление (канал B)|
| ENA    | 27   | PWM скорость         |

### 3.4 `light_ctrl` — управление освещением

- 3 канала: головной (`head`), задний (`tail`), салон (`cabin`)
- Управление через GPIO (HIGH/LOW)
- Команда `"all"` — все каналы одновременно

**GPIO (пример)**:

| Свет   | GPIO |
|--------|------|
| head   | 32   |
| tail   | 33   |
| cabin  | 18   |

### 3.5 `horn` — звуковой сигнал

- Пьезо-бузер с активным управлением (PWM для тона)
- `"short"` — 200 мс
- `"long"` — 800 мс
- `"off"` — отключение

**GPIO**: 19 (пример)

### 3.6 `battery_monitor` — мониторинг батареи

- Чтение напряжения через ADC (делитель напряжения)
- Конвертация в проценты (0–100%)
- Периодический опрос (каждые 10 с)
- Предупреждение при низком заряде (поле `error` в state)

**GPIO**: ADC1_CH0 (GPIO 36)

### 3.7 `cmd_handler` — обработка команд

- Парсинг JSON с помощью cJSON (входит в ESP-IDF)
- Маршрутизация команд по полю `action`:
  - `speed` → `motor_driver`
  - `stop` → `motor_driver` (плавная остановка)
  - `estop` → `motor_driver` (немедленная остановка)
  - `direction` → `motor_driver` (только при speed=0)
  - `light` → `light_ctrl`
  - `horn` → `horn`
  - `config` → `train_config` + обновление параметров `motor_driver`
- Валидация: игнорировать невалидные команды, логировать ошибки

### 3.8 `state_reporter` — публикация состояния

- Сбор состояния из всех компонентов
- Формирование JSON
- Публикация в `train/<id>/state` (retained) периодически (каждые 2 с)
  и при изменении состояния
- Ответ на `ping` → публикация в `train/<id>/pong`

### 3.9 `train_config` — конфигурация

- Хранение в NVS Flash:
  - `id` — идентификатор поезда
  - `model` — название модели
  - `accel_rate`, `decel_rate`, `max_speed`
- Обновление через MQTT-команду `config`
- Значения по умолчанию в `sdkconfig.defaults`

## 4. Последовательность загрузки

```
1. NVS Flash init
2. TCP/IP stack init
3. Event loop init
4. train_config — загрузка конфигурации из NVS
5. wifi_sta — подключение к AP
6. mqtt_client — подключение к брокеру, announce, подписки
7. motor_driver — инициализация PWM, H-мост
8. light_ctrl — инициализация GPIO
9. horn — инициализация PWM
10. battery_monitor — запуск периодического опроса ADC
11. cmd_handler — регистрация обработчика MQTT-сообщений
12. state_reporter — запуск периодической публикации состояния
```

## 5. Безопасность работы

- **Направление**: меняется только при скорости 0 (проверка в `cmd_handler`)
- **E-stop**: всегда срабатывает немедленно, независимо от текущего состояния
- **Потеря связи**: при отключении WiFi/MQTT — плавная остановка через 5 с
- **Низкий заряд**: при <10% — автоматическое ограничение скорости, при <5% — остановка
- **Watchdog**: аппаратный WDT для защиты от зависания

## 7. Назначение GPIO (сводная таблица)

| GPIO | Функция           | Режим       |
|------|--------------------|-------------|
| 25   | Motor IN1          | Output      |
| 26   | Motor IN2          | Output      |
| 27   | Motor ENA (PWM)    | PWM Output  |
| 32   | Light — head       | Output      |
| 33   | Light — tail       | Output      |
| 18   | Light — cabin      | Output      |
| 19   | Horn (buzzer PWM)  | PWM Output  |
| 36   | Battery ADC        | ADC Input   |

> **Примечание**: конкретные GPIO зависят от выбранного модуля ESP32.
> Для ESP32-C3/S3 нумерация отличается — скорректировать при выборе модуля.

## 9. Зависимости от пульта управления

Прошивка поезда полностью зависит от протокола, реализованного в `train-control`.
Ключевые файлы для справки:

| Файл в train-control                                      | Что смотреть                       |
|-----------------------------------------------------------|------------------------------------|
| `PROTOCOL.md`                                             | Полная спецификация протокола      |
| `sdkconfig.defaults`                                      | SSID, пароль, порты                |
| `components/train_controller/train_controller.c`          | Логика формирования команд         |
| `components/mqtt_broker/mqtt_broker.c`                    | Поведение брокера, LWT             |
| `components/event_bus/include/event_bus.h`                | Типы событий                       |
